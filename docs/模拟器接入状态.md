## 各平台要点

### iOS

- **触摸/按键/键盘**都走私有接口（`kcode-sim-hid`），需要完整 Xcode。
  - 触摸：`IndigoHIDMessageForMouseNSEvent`，第 7 参 `IndigoHIDEdge` **必须**
    按落点标（1=左 / 3=下），否则底部上滑与边缘返回**完全不生效**（§3.47）。
  - 硬件键：`IndigoHIDMessageForButton`，target 必须是 `0x33`、
    direction 必须 1/2 成对（§3.47）。
  - 键盘：`IndigoHIDMessageForKeyboardArbitrary(usage, dir)`，用量码表在
    Rust 侧（有测试钉住），**只支持 ASCII**（§3.49）。
- **画面**：常驻窗口流（ScreenCaptureKit）已验证，29.5fps / 每帧约 2ms。
  helper 会把画面**裁到设备屏幕**（首帧+周期性检测），所以「所见即可点」；
  模拟器自己的工具栏不在画面里（§3.47）。
- 失败回退：流不可用时自动退到逐帧截图（`simctl io screenshot`，约 118ms/帧）。

### Android

- **触摸/按键**走 `adb shell input`，已验证。
- **键盘**走 `adb shell input text`，已验证。三个要点（§3.50）：
  - 文本必须用**单引号包住**，否则空格/分号被设备端 shell 吃掉（也是注入面）；
  - `input` 命令会把字面 `%s` 替换成空格，**没法转义**——按 `%s` 切开分段发送；
  - 退格/回车/Tab/Esc 走 `input keyevent`（`input text` 表达不了它们）；
  - **只支持 ASCII**（非 ASCII 在设备端抛 NPE，一个字都打不进去）。
- **画面**：⚠️ 窗口镜像已接通但**出帧不稳定**（见「已知问题」）。
  逐帧截图路径正常，未出帧时会自动回退。

### 小程序

- 触摸是**元素级**（`Element.tap`）：可点画面上的热区，但不是坐标触摸。
- **没有键盘通道**：自动化协议只能往指定元素填值（`Element.input`），
  无法表达「用户按了某个键」（§3.50）。`can_type` 为 false。
- 画面走 `App.captureScreenshot`（约 0.8fps，接口本身慢）。
- 自定义组件宿主的 tap **静默无效**，已在 `pick_clickable` 里剔除（§3.41）。

### 鸿蒙

- **触摸、按键、键盘全部未在真机验证**（本机无 hdc、无 DevEco）。
  `can_input` 与 `can_type` 都是 false，界面如实显示「未接入」并说明原因。
- 注意：**不能照搬 iOS 那套**。iOS 能自己编 HID 用量码是因为能 `dlopen`
  SimulatorKit（**进程内**接口）；hdc 是**外部命令**（与 adb 同层），
  只能调它已有的子命令。有没有打字功能只能拿真机试（§3.50）。

## 已知问题

1. **Android 窗口流出帧不稳定**（本机实测）：同参数连跑，有时 1 秒内出帧、
   有时 20 秒连 stderr 都空。出帧时裁剪**完全正确**（帧比例 0.4614 vs
   设备 0.4615）。用户手动使用画面正常。

   **收尾时发现一个很可能的原因**：清理时找到 **4 个残留的
   `kcode-window-cast` 进程**（ppid 全为 1，是我反复跑测试留下的孤儿），
   全都抓着同一个 qemu 窗口。多个进程竞争同一个窗口的 SCK 捕获，
   完全可能表现为「有时出帧、有时没有」。**下一轮先确认没有残留进程再复测**
   （`pgrep -fl kcode-window-cast`），不要一上来就怀疑代码。
   若确认是这个原因，那就不需要加重试——只要保证 helper 的**单例性**
   （启动前清理/复用在跑的）。
2. **画面区拖动会被浏览器选中**（已修，§3.48）：WebKit 给选中的图片铺一层
   高亮（蓝色）。已用 `user-select: none` 修掉，并加了静态样式防护测试。
3. 一条 Android 去重测试在**动屏**（状态栏时钟/动画）下会失败——已改成
   自诊断（连续三帧都变则如实报告「屏幕在动」），不再伪装成缺陷。

## 能力位（后端 → 前端）

`PlatformStatus` 有两位，分开是因为它们在四平台上确实不同：

- `can_input`：能否发送**触摸**；
- `can_type`：能否输入**文本**（键盘）。

`input_mode` 表达形态：`coordinate`（按坐标点）/ `element`（只能点元素）/
`none`（只读）。界面据此决定画可点画面还是元素列表。

**不支持的平台要明确报错并说明原因**，绝不静默丢弃——「点了没反应」
比「告诉你不支持」难排查得多。

## 怎么复跑验证

```bash
bash scripts/build-sim-hid.sh        # 编译 iOS 注入 helper（含键盘）
bash scripts/build-window-cast.sh    # 编译窗口捕获 helper
npm run stats                        # 全量测试 + 更新统计

# 需要真机的端到端测试（默认 #[ignore]）
cargo test -p kcode-desktop --lib -- --ignored --nocapture --test-threads=1
```
